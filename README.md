# 库存进出管理系统

基于 Python 3.12 + FastAPI + SQLite + 原生 HTML/JavaScript，无需独立数据库服务和前端构建。

## 安装和启动

### Windows（推荐）

安装 Python 3.12，完整解压项目后，双击根目录的 **`start.bat`**。
脚本会创建虚拟环境、在缺少依赖时联网安装，启动服务并检查页面资源，然后自动打开浏览器。
首次启动还会在命令窗口要求创建管理员账号和密码（至少10位，输入密码不显示字符）。没有默认账号或密码。已有管理员时不会重复询问。
启动后浏览器明确进入 `/login` 登录页，例如 `http://127.0.0.1:8000/login`。该地址始终显示账号、密码和登录按钮，即使浏览器已有会话，也不会自动跳过登录表单；访问库存页时仍可恢复有效会话。退出或会话过期后返回登录地址。
端口8000已被占用时自动选择8001～8020；请使用启动窗口实际显示的网址。保持窗口打开，Ctrl+C停止。

**不要直接双击 `app/static/index.html`**，也不要只下载这个文件；它需要 Python 服务提供样式、脚本和数据库接口。
macOS / Linux 也可以执行 `python3 start_local.py` 自动安装、启动和打开浏览器。

自动启动入口只监听本机，供本地使用；局域网共享请按下方命令启动并确认防火墙设置。

### 手动启动（macOS / Linux）

```bash
./setup.sh
./start.sh
```

浏览器访问 `http://localhost:8000`。API 文档位于 `/docs`，健康检查为 `/api/health`。
首次请求自动创建数据库。默认数据文件是 `data/inventory.db`，重启后保留。
可使用 `PORT=8080 ./start.sh` 更改端口，或设置 `INVENTORY_DB=/绝对路径/inventory.db` 更改数据位置。

`requirements.txt` 声明直接依赖，`requirements.lock` 固定当前验证过的全部依赖；安装脚本使用后者。

## 页面和使用顺序

首页为**总库存**，采用侧栏导航、顶部任务栏、数量看板和商品表格。通过导航分别进入：

- `/inventory`：总库存，搜索、状态/成色/款式/尺寸筛选、分页、流转和导出。
- `/inventory/new`：新建库存，独立表单。
- `/movements`：全部流转流水，含操作时间、操作人和数量。
- `/reports`：期间出库、销售统计及 Excel 导出。
- `/settings`：自定义库存状态、成色、款式、尺寸及新增商家。
- `/accounts`：管理员创建和管理员工账号。
- `/login`：员工登录。所有库存接口都要求登录，健康检查除外。

各页面可直接访问、刷新，也支持浏览器前进后退。

1. **登记商品**：登录后点击“新建库存”，填写唯一编号、名称、款式、成色、数量、尺寸和时间。操作人自动锁定当前登录账号，不能手动修改。成色可选择或手动填写，如“九成新”；它与库存位置/状态是两个独立字段。位置默认“仓库”。
2. **流转 / 调取**：在总库存表点击“流转”，选择目标状态、**本次流转数量**、时间和备注，操作人自动锁定当前账号。内置仓库、第三方鉴定、商家、已售、退回到仓库，也支持自定义状态；同位置操作可记录所选数量的调取。
3. **商家管理**：商家状态下必须填写商家。新名称在保存记录后会自动成为下拉建议，也可从新建页或自定义选项页预先添加商家。
4. **追溯记录**：商品行“流水”查看单品记录；“流转记录”页查看全部流水。
5. **期间汇总**：在统计报表页选择起止时间，分别查询出库/销售件数、操作次数和去重商品批次数。
6. **Excel 导出**：包含全部内置、自定义状态及状态件数汇总，以及款式、成色、尺寸、数量；期间导出额外包含统计和带数量的流水。库存页筛选不影响“全部库存”导出。

### 自定义选项

库存页“自定义状态”、表单各字段旁的“自定义”按钮，可立即新增并同步到筛选和流转下拉列表。款式、成色、尺寸也可在商品表单直接输入，保存商品后自动成为常用选项。

在“自定义选项”页可管理名称、修改自定义状态的统计分类，或删除未使用选项。改名会同步现有商品；库存状态改名也同步历史流水。已被商品或历史流水使用的选项不能删除。五个系统状态保留，不能改名或删除。

库存状态必须归入“在库”“外出”或“已售”：例如“待上架”归入在库，“送修中”归入外出。修改分类会影响此前记录的统计归属，确认后再修改。

### 统计和时间规则

- 出库：从在库类状态转至外出或已售类状态。鉴定转商家不重复计为仓库出库。自定义状态按配置的分类参与统计。
- 销售：从非已售类状态变为已售类状态；退回后再次出售，销售次数和销售件数再次增加。出库和销售的去重批次数按原始批次计算，拆分不会虚增原始批次数。
- 期间明细包含登记、流转和同状态调取；起止时间均包含边界。初次登记为已售会计入销售，但没有仓库出库记录。
- 页面输入和展示使用浏览器本地时区，后端统一保存 UTC，Excel 时间列明确标注 UTC。
- 新操作时间不能早于同一商品的上一条记录。系统允许业务所需的状态互转，以记录退货、撤销销售等实际情况；请通过新流水记录纠正状态。
- 每个编号代表一批同款、同尺寸、同成色商品，数量为正整数（1～1,000,000）。流转可选择1至当前可用数量之间的整数。部分流转会生成一个 `原始编号-S随机标识` 的子分项，原位置保留余量；全部流转直接更新该分项的位置。前后总件数保持不变，不自动合并同位置的不同分项。
- 示例：入库100件，转30件至鉴定后，总库存中显示原仓库70件、鉴定30件；再从仓库转20件至Aloha商家，显示仓库50件、鉴定30件、Aloha20件。可以继续选择任何分项分次流转、销售或退回。
- 同位置、同商家的操作只记录调取数量，不减少实际库存；同为“商家”但更换商家则按流转处理。
- 点击任一分项的“流水”，可追溯原始批次和全部子分项。拆分流转只生成一条实际转移流水，不额外重复计入入库。Excel中新增原始批次编号列。不提供价格或销售额统计。

### 旧数据升级

首次 API 请求自动为旧数据库增加缺少的商品字段、批次关联、账号和会话表。已有商品和流水保留，最早版本无数量字段的数据默认为1；此前已录入的数量保留。旧流水的操作人原样保留，新流水强制使用当前登录账号。迁移可重复执行。升级前建议先备份 `data/inventory.db`。

### 员工登录与权限

首次运行 `start.bat`（或 `start.sh`）按终端提示创建管理员；也可手动执行 `.venv/bin/python -m app.manage_admin`，Windows使用 `create_admin.bat`。管理员登录后进入“员工账号”，为每位员工创建独立账号和密码。账号支持中文姓名、字母、数字、点、下划线、短横线；用户名不可修改，因此历史操作人始终对应同一账号。

| 角色 | 库存查询 | 入库、流转、商家及选项管理 | Excel导出 | 员工账号管理 |
| --- | --- | --- | --- | --- |
| 管理员 | 是 | 是 | 是 | 是 |
| 员工 | 是 | 是 | 是 | 否 |
| 只读人员 | 是 | 否 | 否 | 否 |

入库和流转的操作人字段为只读；后端忽略手动提交的操作人，强制从登录会话获取，因此修改网页或直接调用接口也不能冒用他人。各账号共享库存，不按员工隔离商品。

管理员可以停用账号、修改角色、重置密码；这些操作会撤销对应账号已有登录。必须保留至少一个启用管理员。员工可通过右上角修改自己的密码，改密后需重新登录。

密码使用带随机盐的scrypt散列；会话保存在数据库，12小时过期，Cookie设为HttpOnly和SameSite=Strict，写请求校验CSRF令牌。退出或改密会撤销登录。连续5次失败按来源地址与账号限流15分钟。没有开放注册接口，也没有默认密码。

## 验证

### 导入虚拟测试库存

Windows 安装依赖后双击 `seed_demo.bat`，其他系统在项目目录执行 `.venv/bin/python -m scripts.seed_demo`，然后打开或刷新总库存。

生成100件拉夫劳伦Polo衬衫，每件独立编号（`DEMO-RL-POLO-001`～`100`）、数量1。全新/有使用痕迹各50件，L/M各50件，每种成色与尺寸组合25件；固定随机分配到鉴定仓50件、Aloha商家50件。自动新增“鉴定仓”状态和“Aloha”商家，每件有入库、流转两条虚拟流水，可用于期间统计测试。

所有流水标注“虚拟测试数据”，时间在生成日前一周内。重复运行不会重复添加或覆盖已有商品；正式使用前请换用不含测试数据的数据库。与已有库存混合使用前请先备份。

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
```

测试使用临时数据库，覆盖部分流转、数量守恒、并发超额拦截、同位置调取、跨商家流转、批次追溯和去重、员工身份防冒用、权限、CSRF、账号停用与会话撤销，以及原有商品、字段、报表、迁移和Excel功能。

## 数据备份与部署

```bash
.venv/bin/python scripts/backup.py
# 或指定一个尚不存在的目标文件
.venv/bin/python scripts/backup.py backups/manual.db
```

备份脚本使用 SQLite 在线备份接口，可在服务运行时执行。请将备份复制到另一台机器或可靠存储。
恢复时停止服务，将备份复制至 `data/inventory.db`（先保留现有文件），再启动服务。

局域网共享需在服务器上运行 `start.sh` 或手动用 `--host 0.0.0.0` 启动uvicorn；`start.bat`的自动浏览器入口默认仅允许本机访问。不同员工访问同一台服务器并用各自账号登录。公网部署仍需HTTPS，并设置 `COOKIE_SECURE=1`；反向代理需正确传递Host和协议以通过同源校验。SQLite适合小规模部署，数据目录必须持久保存。数据库备份含密码散列和会话，需妥善保护。
