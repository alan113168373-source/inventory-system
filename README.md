# 库存进出管理系统

基于 Python 3.12 + FastAPI + SQLite + 原生 HTML/JavaScript，无需独立数据库服务和前端构建。

## 安装和启动

```bash
./setup.sh
./start.sh
```

浏览器访问 `http://localhost:8000`。API 文档位于 `/docs`，健康检查为 `/api/health`。
首次请求自动创建数据库。默认数据文件是 `data/inventory.db`，重启后保留。
可使用 `PORT=8080 ./start.sh` 更改端口，或设置 `INVENTORY_DB=/绝对路径/inventory.db` 更改数据位置。

`requirements.txt` 声明直接依赖，`requirements.lock` 固定当前验证过的全部依赖；安装脚本使用后者。

## 使用顺序

1. **登记商品**：填写唯一商品编号、名称、初始状态、操作人和时间，每个编号代表一件物品。
2. **流转 / 调取**：在库存表中选择商品，填写目标状态、操作人、时间和备注。支持仓库、第三方鉴定、商家、已售、退回到仓库五种状态；同状态操作可记录物品调取及用途。
3. **商家管理**：商家状态下必须填写商家。输入新名称后保存流转记录，会自动保存在商家下拉建议中；也可点击“新增常用商家”预先添加。点击商家输入框或输入名称可选择建议。
4. **追溯记录**：点击“查看流水”，查看每次操作的前后状态、商家、时间、操作人和备注。历史流水保留，当前状态随最新操作更新。
5. **期间汇总**：选择起止时间，查询出库和销售次数、去重商品件数，以及期间所有操作明细。
6. **Excel 导出**：全部库存导出包含所有五种状态及状态件数汇总；期间导出额外包含所选时间范围内的统计和流水。库存页筛选不影响“全部库存”导出。

### 统计和时间规则

- 出库：从“仓库”或“退回到仓库”转至“第三方鉴定”“商家”或“已售”。鉴定转商家不重复计为仓库出库。
- 销售：从非“已售”状态变为“已售”；退回后再次出售，销售次数增加，去重件数仍按商品编号计算。
- 期间明细包含登记、流转和同状态调取；起止时间均包含边界。初次登记为已售会计入销售，但没有仓库出库记录。
- 页面输入和展示使用浏览器本地时区，后端统一保存 UTC，Excel 时间列明确标注 UTC。
- 新操作时间不能早于同一商品的上一条记录。系统允许业务所需的状态互转，以记录退货、撤销销售等实际情况；请通过新流水记录纠正状态。
- 当前版本按件管理，不提供批量数量、价格或销售额统计。

## 验证

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
```

测试使用临时数据库，覆盖状态流转、重复编号、商家保存、时间范围边界、销售去重、数据持久化、非法输入及 Excel 单元格内容和公式注入防护。

## 数据备份与部署

```bash
.venv/bin/python scripts/backup.py
# 或指定一个尚不存在的目标文件
.venv/bin/python scripts/backup.py backups/manual.db
```

备份脚本使用 SQLite 在线备份接口，可在服务运行时执行。请将备份复制到另一台机器或可靠存储。
恢复时停止服务，将备份复制至 `data/inventory.db`（先保留现有文件），再启动服务。

当前版本面向受信任的内部使用环境，没有登录和权限管理，操作人由手动输入，不能作为经过身份认证的审计记录。请勿直接暴露到公网；如需多人对外使用，应先配置登录、权限和 HTTPS。SQLite 适合小规模部署，数据目录必须持久保存。
